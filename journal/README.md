# 复盘数据中枢 · 联动规则（三窗口共用）

所有"窗口"（豆包对话）彼此隔离，但都通过**同一个 GitHub 仓库 + 飞书复盘中心**共享状态。本文件是联动的"接口约定"。

- **飞书复盘中心（手机可读）**：https://my.feishu.cn/file/YvY3bywokoMdPxxs9MZchh0EnBc （每日复盘顶部最新，由复盘窗口用 lark-cli markdown +patch/+overwrite 更新）

## 一、三个窗口的分工

| 窗口 | 角色 | 读 | 写 |
|---|---|---|---|
| **主窗口（豆包）** | 日常问答、临时查票、盘中操作 | 全部 | 视情况更新 live_state |
| **A股实战体系窗口** | 五轨体系、盘前/盘中/定时任务、涨停雷达 | 全部 | live_state（实时信号/作战计划/持仓） |
| **复盘窗口（新）** | 成交即报、收盘深度复盘、战绩统计、体系迭代 | 全部 | trades.csv、账户统计.md、review/、飞书报告、live_state次日清单 |

**单一事实来源优先级：**
1. 持仓 / 资金 / 可用 → 以**中信证券APP**为准（人报）
2. 实时行情 / 涨停 / 炸板 → 腾讯 qt.gtimg.cn + 东财涨停池（雷达脚本）
3. 作战计划 / 当日信号 / 观察池 → `live_state.md`
4. 历史成交 / 战绩 → `journal/trades.csv`
5. 每日复盘归档 → `review/YYYY-MM-DD.md` + 飞书复盘中心

## 三、成交即报格式（用户报单，复盘窗口入表）

- 买入：`水晶 20.5 买200 轨1` → 新建一行（代码/名称/轨道/板块/买入理由/止损自动补）
- 卖出：`水晶 23 清仓` → 定位该票未清仓行，补清仓价/日期/原因/盈亏/判定
- 只发关键数字即可，复盘窗口负责补全代码、板块、金额、止损并即时回写
- 若报的是计划外/体系外交易，照实入表并在"判定"标注（不替用户美化）

## 四、trades.csv 字段（一笔完整交易一行）

建仓日期｜代码｜名称｜轨道｜板块｜买入价｜股数｜买入额｜买入理由｜止损位｜清仓日期｜卖出价｜卖出额｜卖出原因｜持有交易日｜盈亏额含费｜盈亏%｜判定(对/错/违纪)｜复盘备注

## 五、每日复盘流程（收盘后，复盘窗口）

1. 读 `live_state.md` 当日全部记录（8:50/9:25/9:35/10:30/13:30/14:30/15:10 各点）
2. 核当日成交（用户报单 + 雷达）→ 补全 trades.csv
3. 拉腾讯/东财收盘数据核对大盘、主线、涨停梯队、炸板率、一进二晋级率
4. 输出深度复盘（见角色卡框架）→ 归档 `review/YYYY-MM-DD.md`
5. 重算并更新 `账户统计.md`（胜率、盈亏比、各轨、零违纪进度）
6. 更新 `live_state.md` 顶部：持仓/资金/次日轨3候选/轨1 if-then/明日风险
7. 同步一份手机可读版到飞书"A股复盘中心"

## 六、铁律
- 实时数据不编造、带正确年份；资金以券商APP为准
- 沪深主板 60/00/003，无创业板/科创板/北交所
- 单票风险 ≤250 元为唯一硬闸门；多标的可并行、永不补仓
- 只呈现不筛选 vs 可出手：全方向扫描给全景，买入只在权限内五轨信号
